# Checkpoints, Hugging Face Backup and Recovery

## 1. Why checkpoint formats matter

The P01 training loop writes two **different** checkpoint categories. Confusing them can silently restart training or cause a resume failure.

| File | Typical size from the run | Contents | Correct use |
|---|---:|---|---|
| `last.pt` | About **3.8 GB** | Full FP32 model state, Adam optimizer, GradScaler state, RNG, epoch/next batch/step counters, fingerprint | **Resume training only** |
| `best_online_f1.pt` | About **636 MB decimal** | Model weights (float tensors stored as FP16) and selection metadata | Inference / selected Dev checkpoint |
| `best_dev_loss.pt` | About **636 MB decimal** | Model weights and selection metadata | Alternative inference checkpoint |
| `config.json` | Small | Effective runtime config, fingerprint and source paths | Provenance / resume validation |
| `dev_epoch_001.json` | ~6 KB | Aggregate Dev loss and subgroup metrics | Evaluation audit |

Exact sizes vary with serialization format. `best_online_f1.pt` was restored locally, and its checkpoint contained `format_version`, **674 `model_state_dict` entries**, `epoch=1`, `global_step=4737`, Dev metrics and selection metadata.

Best snapshots being stored with FP16 tensors **does not mean** the model was trained in AMP. Training used full FP32. On load, call `model.load_state_dict(checkpoint['model_state_dict'], strict=True)` on the already instantiated model.

## 2. Private backup location

The team used a private Hugging Face **model** repository:

```text
AhmedLabib1/rtc-sdd-research-checkpoints/
└── experiments/
    └── p01_xlsr_aasist_official_like_fp32/
        ├── last.pt
        ├── best_dev_loss.pt
        ├── best_online_f1.pt
        ├── config.json
        └── dev_epoch_001.json
```

Additional `.sha256.json` integrity sidecars may be present. The repository is **private**; access depends on authorization and a token. Do not publish credentials or bypass the dataset's distribution restrictions.

## 3. Secure credential handling

On Kaggle, store `HF_TOKEN` in **Secrets** and read it when a storage operation is actually needed:

```python
from kaggle_secrets import UserSecretsClient
TOKEN = UserSecretsClient().get_secret('HF_TOKEN')
assert TOKEN, 'HF_TOKEN is unavailable'
# Do not print TOKEN or serialize it into notebooks/reports.
```

Do not set up automatic Hugging Face checkpoint uploads during Progress inference. The trained checkpoint is already restored and the user intentionally disabled Progress-score cloud backups for submission generation. Local partial score files can help resume **within the same surviving Kaggle working directory**.

## 4. Restore only the model checkpoint for inference

Inside Kaggle, with `huggingface_hub` available:

```python
from pathlib import Path
from huggingface_hub import hf_hub_download
from kaggle_secrets import UserSecretsClient

ROOT = Path('/kaggle/working/RTC-SDD-Research')
REPO = 'AhmedLabib1/rtc-sdd-research-checkpoints'
PREFIX = 'experiments/p01_xlsr_aasist_official_like_fp32'
TOKEN = UserSecretsClient().get_secret('HF_TOKEN')

for name in ['best_online_f1.pt', 'config.json', 'dev_epoch_001.json']:
    path = hf_hub_download(
        repo_id=REPO, repo_type='model', filename=f'{PREFIX}/{name}',
        token=TOKEN, local_dir=ROOT / 'outputs'
    )
    print('Restored:', Path(path))
```

With `local_dir=ROOT/'outputs'`, the returned filename includes the nested `experiments/...` prefix; verify the actual path and do not guess it. Restore `last.pt` **only if planning an intentional training continuation**; it is much larger and not needed for predictions.

## 5. Correct model-only load sequence

```python
import torch
from rtcsdd.models.xlsr_aasist import load_xlsr_aasist

model = load_xlsr_aasist(OFFICIAL, PRETRAINED, 'cuda:0')
ckpt = torch.load(BEST_CHECKPOINT, map_location='cpu', weights_only=True)
model.load_state_dict(ckpt['model_state_dict'], strict=True)
model.eval()

with torch.inference_mode():
    logits = model(batch_audio.to('cuda:0'))
    spoof_scores = torch.softmax(logits.float(), dim=-1)[:, 0]
```

`OFFICIAL`, `PRETRAINED`, `BEST_CHECKPOINT` and `batch_audio` must come from your validated runtime. Verify metadata (`epoch`, `global_step`, `selection_metric`, `config_fingerprint`) before making score claims.

## 6. True resume is different

`last.pt` is generated by `training/checkpointing.py::save_resume` and includes optimizer, RNG, checkpoint format version and `next_batch`. The trainer checks the config fingerprint, dataset root, pretrained source and manifest. A model-only best snapshot cannot restore Adam history or exactly resume an interrupted optimizer state.

If training continuation is deliberately required:

1. Restore `last.pt` and `config.json` into the **same output directory**.
2. Verify their origin, fingerprint, code version, data path and available disk.
3. Use `--resume` with `xlsr_aasist_finetune` and the intended epoch target.
4. **Never** run a non-resume training command over a completed experiment directory.
5. Document which epoch/step the continuation started from.

`read_resume` uses `torch.load(..., weights_only=False)` to restore trusted optimizer/RNG objects. **Never deserialize an untrusted `.pt`**; PyTorch checkpoints can contain unsafe serialized content.

## 7. Backup operations (training-only, optional)

The storage CLI supports verified download and manual upload:

```bash
python -m rtcsdd.storage.cli download \
  --repo-id AhmedLabib1/rtc-sdd-research-checkpoints \
  --remote-path experiments/p01_xlsr_aasist_official_like_fp32/last.pt \
  --destination /path/to/last.pt
```

Consult `src/rtcsdd/storage/cli.py` for exact supported args (`--overwrite` is optional for download). The automatic checkpoint backup manager is controlled by the effective run config. The source JSON patch may default `checkpoint_backup.enabled` to **false**, whereas the actual Kaggle training run explicitly enabled uploads at runtime. **Don't infer actual cloud behavior from a newly restored default JSON alone.**

## 8. Disk and failure handling

- Checkpoint saving is **atomic** via a temporary file then replacement. It needs additional free disk beyond the final file size.
- The Kaggle working directory is temporary; files are not guaranteed to survive a reset.
- If disk space is tight, avoid loading/reserializing `last.pt` for ordinary inference. Use the best model-only checkpoint.
- Restore only required files; do not automatically upload partial Progress scores.
- Log hashes and metadata in a report, not secret token values.
